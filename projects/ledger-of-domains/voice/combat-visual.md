# Combat — Visual Vocabulary

Load with `combat.md` when writing a fight, then read only the family files that fit. Options, not templates: one or two per fight, never as the spine of a chapter, never in the same order twice. Sources and unconfirmed readings live in `combat-visual-log.md` (do not load).

**Not sword techniques.** Most references show blades, but every family is a shape of movement and space. It applies equally to fists, legs, a forearm guard, a Domain, a thrown object or a barrier.

**Strategy, not concepts or mechanism.** Notes must read as generalized strategy (what each side reads, spends, hides and answers); if a note could only be understood by someone who knows the reference's power system, rewrite it until it can. The references come from other works with their own power systems. Take the strategy (what each side reads, spends and answers), never their concepts, names or terms into this world (closed spaces, guaranteed-hit effects, domain expansion, etc.). Read "blade" as "whatever carries the strike" and "guard" as "whatever holds the line".

## Reading a still
Weight (which limb carries it) · Axis (direction, arc radius) · Contact (what touches, what it leaves) · Unknowns stay unknown: timing, scale and blow order come from the scene, not the image.

## Families (index)
One file per family in `voice/combat-visual/`. Each family is a shape, not an image.

## Against overuse
- Vary entries; do not open consecutive fights with the same shape.
- A striking pose is not a beat; each beat needs a micro-objective (`combat.md` §3).
- Images show moments; prose needs the cause between them.
- POV decides what is perceived (`bundles/write/action.md`).

## Maintenance
This file is only the index. Load it, pick the one to three families that fit the scene, and read only those files. A new image adds at most one line to an existing family file; create a family file (and an index row) only for a genuinely new shape. Keep each family file under ~12 lines.
